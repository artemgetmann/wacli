Why the tests live where they do

One Go package owns the behaviorinternal/store/handled_unread.go
internal/store/handled_unread_test.go

Keep the test beside the code. A developer can run go test ./internal/store to check that package. Same-package tests can exercise private helpers; a sibling test using package store_test can exercise the public API. Go excludes test files from normal builds.

The whole product owns the behaviorCLI reply → WhatsApp → Web badge

A separate, opt-in acceptance suite makes sense here. It needs a linked account and an independent way to observe the badge. GitHub’s Go CLI follows this split: it keeps command tests beside the command and has a separate suite for real GitHub interactions.
